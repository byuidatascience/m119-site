# m119-site

Published Quarto course site for **Math 119 — Applied Calculus for Data Analysis** at BYU-Idaho. Renders to `site/_site/` and is deployed to GitHub Pages.

## Project Purpose

**This is**:
- The student-facing course website for Math 119 (BYU-Idaho).
- A Quarto site (`site/_quarto.yml`) whose content lives in `.qmd` files under `site/class/`, `site/flex/`, `site/definitions/`, plus `site/index.qmd` and `site/schedule.qmd`.
- The publish/delivery side of the m119 pipeline. Content is produced upstream (PMWiki + converter scripts in the sibling `m119-master` repo) and lands here as rendered Quarto pages.
- Deployed via GitHub Actions (`.github/workflows/publish.yml`); the `daily_update.yml` workflow refreshes the "today" pointer (`site/_today.qmd`) for the front page.

**This is NOT**:
- The source/authoring side. PMWiki sync, RMarkdown→Quarto conversion, and schedule generation live in `m119-master` — do not run those tools from here.
- A Canvas LMS integration. Canvas course content (assignments, quizzes, modules) is managed elsewhere; this repo is the public web companion only.
- A Python application. The `pyproject.toml`/`uv.lock` are scaffold residue from the upstream canvas-toolbox drop. The one **exception** is `tools/generate_schedule.py`, which is actively load-bearing (invoked daily by `.github/workflows/daily_update.yml` to refresh `site/_today.qmd`). Its canonical authoring lives upstream in m119-master per the schedule-ownership rule below — the copy here is a mirror, and edits made here should be back-propagated upstream. The active surface is `site/` plus that one script plus `.github/workflows/`.
- A place for student PII or gradebook data.

**Audience**:
- Math 119 students (consumers of the published site).
- The instructor (Chaz) editing class/flex/definition pages locally and pushing.
- LLM agents helping with content edits, Quarto config tweaks, or diagnosing render/publish issues.

## Working Style

This project follows the behavioral discipline defined in `knowledge/behavioral_discipline.md` (co-located in this repo at the canonical path). **Read that file before doing non-trivial work in this repo.**

The four no-override principles — **P-001 Read Before Claiming, P-003 Stop on Defect, P-007 Pull Don't Push, P-010 Respect Intent** — apply unconditionally; the other six (P-002, P-004, P-005, P-006, P-008, P-009) have documented override conditions in the discipline file.

**Project-specific rules**:
- **Quarto, not Jupyter, not RMarkdown.** Pages are `.qmd`. Quarto is the renderer. Don't introduce alternative formats here.
- **`_today.qmd` is auto-generated.** Do not hand-edit it — it's regenerated by the `daily_update.yml` workflow (and originally by `tools/generate_schedule.py` in the m119-master pipeline). Hand edits will be overwritten.
- **`site/_site/` is build output.** Do not commit it; do not hand-edit it. Let Quarto regenerate it.
- **Schedule ownership lives upstream.** `schedule.qmd`, `schedule_config.yml`, `schedule_full.json`, and `_today.qmd` are produced by the m119-master pipeline; `tools/generate_schedule.py` here is a mirror copy that CI runs daily. The intended workflow: edit the schedule config in m119-master, sync downstream. If you edit `schedule_config.yml` or `tools/generate_schedule.py` here directly (because m119-master isn't open in front of you), **back-propagate the change to m119-master afterwards** so the two don't drift.
- **No Sunday due dates.** BYU-Idaho hard rule — applies to anything date-bearing on this site (schedule entries, assignment references, "next class" pointers). If you see one, flag it.
- **For content edits, point faculty at [FACULTY.md](FACULTY.md); for non-trivial work, point at this AGENTS.md.** The root `README.md` is now a thin pointer to both — don't expand it into a project explainer.
- **Render locally before pushing.** `cd site && quarto render` to validate. CI also renders, but catching errors locally is cheaper than red CI runs.

## External System Lessons

**GitHub Pages publish (`.github/workflows/publish.yml`)**:
- *Behavior*: Quarto's `freeze: auto` caches rendered outputs. If a `.qmd` referencing an external resource (image, PDF, CSV) renders successfully once and the resource later changes, the cached render may not pick up the change.
- *Why it matters*: Students see stale content even though the `.qmd` source looks correct.
- *How to handle*: When changing referenced resources under `site/assets/`, delete the corresponding `_freeze/` subdirectory (if present) and let CI re-render. Alternatively, force a render by editing the `.qmd` to invalidate the freeze hash.

**MathJax in `_quarto.yml`**:
- *Behavior*: The site uses MathJax 3 from a CDN with custom macros (`\ds`, `\diff`). Pages that use these macros depend on the `include-in-header` script block in `_quarto.yml`.
- *Why it matters*: If a page is rendered standalone (outside the project) the macros won't resolve.
- *How to handle*: Always render via the project (`quarto render` in `site/`), not via `quarto render path/to/page.qmd` from elsewhere.
